=== Goals

* To understand conceptually why Magnolia always needs an Author instance and at least one Public instance
* To be able to differentiate between (and access) author and public instances
* To know who uses Author instances
* To know who uses Public instances
* To understand why we normally use two Public instances instead of one.


== Author Instance

image::images/675154043/admincentral2.png[, 700]

** Accessible through the URL http://localhost:8080/magnoliaAuthor[http://localhost:8080/magnoliaAuthor]
** Authors work on the Author Instance - it's where they* create, edit, manage or delete content*
** Reflects the actual state of the editorial content, not the public state of the content
** Usually located in a protected environment, not public to the outside world
** *Only one Author Instance usually exists*
** When edited content should be published, the content is activated
** Activating content pushes the data from the Author Instance to any configured Public Instance(s)


== Public Instance

image::images/675154043/public-instance.png[, 700]

** Accessible through the URL http://localhost:8080/magnoliaPublic[http://localhost:8080/magnoliaPublic]
** *Public instance(s) serve the content or pages to the public world*
** *Receives the content from an Author Instance*
** Authors do not work on Public instances
Each instance should run in its own Application server


[NOTE]
====
Best Practice: Run two public instances for load balancing and fail over safety.
====

.

=== Be aware of '_Public User generated Content'_

It is important to be aware of the content created by public users; a typical example is page comments: +
The public instances have separate DBs and in front is a LB located that balances the requests in between the two public instances.

→ Content from public users would be created only in one of the public instances.

The content must be either shared or synchronized. +
One possible solution is using a JCR cluster for a certain workspace:

== Content's Publication Status

* The '*_status_*' column in the '_Pages App_' or any other Content Apps is the publication status indicator:
+
image::images/675154043/activated-pages.png[, 700]

== Author Instance vs Public Instance(s)

In Magnolia scope, both are the same web-application, only *the configuration* varies


[cols="1,1,1",options="header"]
|===
| Configuration
| Configuration value
| Instance

| +
config/server/admin
| true
| Author

| false
| Public

|===

The ACLs of the anonymous role is always different! And most likely other ACLs too.


[cols="1,1,1",options="header"]
|===
| Instance
| Role
| Access

| Author
| anonymous
| *NO* access to anything - login required.

| Public
| anonymous
| Has read access to *all public pages*.

|===

* Often project-specific roles are different on Author and Public instances, depending on the edit rights and project specs
* Usually located in different network environments
